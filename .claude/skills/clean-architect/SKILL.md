# Clean Architect

Планировщик по чистой многослойной архитектуре для монорепозитория Drivovo.

## Правило зависимостей (Dependency Rule)

Зависимости направлены ТОЛЬКО внутрь — от внешних слоёв к внутренним:

```
Presentation → Infrastructure → Application → Domain
```

Внутренний слой НИКОГДА не знает о внешнем. Domain не импортирует ничего из Application/Infrastructure/Presentation.

## Слои архитектуры

### 1. Domain (ядро)

**Расположение:** `libs/domain/src/`

Содержит бизнес-сущности и правила, не зависящие от фреймворков.

- **Entities** (`entities/`) — интерфейсы с суффиксом `Entity` (CarEntity, UserEntity и т.д.). Представляют ключевые бизнес-объекты с идентификатором (`id`).
- **Value Objects** (`value-object/`) — неизменяемые объекты без идентификатора (Money, Price, Image, Option). Описывают характеристики, а не идентичность.
- **Domain Services** — чистые функции бизнес-логики, не привязанные к конкретной сущности.

**Правила:**
- Все интерфейсы с суффиксом `Entity` являются доменными сущностями
- Entity всегда имеет поле `id: string`
- Value Object НЕ имеет `id`, определяется через совокупность полей
- Никаких зависимостей от фреймворков, HTTP, баз данных
- Экспорт через barrel-файлы (`index.ts`)
- Импорт в приложениях: `import { CarEntity } from 'domain'`

### 2. Application

**Расположение:** `libs/<feature>/src/` или `apps/<app>/application/`

Оркестрирует бизнес-логику через Use Cases.

- **Use Cases** — один класс = одна операция (GetCarByIdUseCase, CreateCreditUseCase)
- **DTOs** — объекты передачи данных между слоями (суффикс `Dto`)
- **Mappers** — преобразование Entity ↔ DTO (суффикс `Mapper`)
- **Port-интерфейсы** — абстракции для Infrastructure (суффикс `Port` или `Repository`)

**Правила:**
- Use Case зависит ТОЛЬКО от Domain и Port-интерфейсов
- Не знает о конкретных реализациях (HTTP, DB)
- Один Use Case — одна ответственность

### 3. Infrastructure

**Расположение:** `apps/<app>/infrastructure/`

Реализации взаимодействия с внешним миром.

- **Repositories** — реализация Port-интерфейсов (HTTP-клиенты, DB-доступ)
- **API Adapters** — адаптеры к внешним сервисам
- **Mappers** — преобразование API-ответов в Domain Entity

**Правила:**
- Реализует интерфейсы из Application слоя
- Может зависеть от фреймворков (Fastify, fetch, ORM)
- Изолирует детали реализации от бизнес-логики

### 4. Presentation

**Расположение:** `apps/<app>/ui/` или `apps/<app>/components/`

UI-компоненты и управление состоянием.

- **Components** — React/Angular компоненты
- **State/Store** — MobX (web), NGXS (admin) — ViewModel, State
- **Providers** — DI-контейнеры, контексты

**Правила:**
- Зависит от Application (Use Cases) и Domain (Entity для типизации)
- Компоненты НЕ содержат бизнес-логику
- State management работает через Use Cases

## Алгоритм планирования фичи

При планировании новой фичи следуй этому порядку:

### Шаг 1: Анализ домена

1. Определить какие Entity затронуты (существующие или новые)
2. Определить нужны ли новые Value Objects
3. Есть ли бизнес-правила, требующие Domain Service

### Шаг 2: Проектирование Application слоя

1. Определить Use Cases (какие операции нужны)
2. Определить DTOs для входа/выхода Use Cases
3. Определить Port-интерфейсы (какие данные нужны извне)
4. Определить Mappers (Entity ↔ DTO)

### Шаг 3: Проектирование Infrastructure

1. Реализации Port-интерфейсов (API-клиенты, репозитории)
2. API-контракты (endpoints, request/response)
3. Mappers для API-ответов

### Шаг 4: Проектирование Presentation

1. Какие компоненты нужны
2. Какой State/Store нужен
3. Как компоненты подключаются к Use Cases

### Шаг 5: Формирование плана

Выдать план в формате:

```
## [Название фичи]

### Domain слой
- [ ] Файлы: ...
- [ ] Описание изменений

### Application слой
- [ ] Файлы: ...
- [ ] Описание изменений

### Infrastructure слой
- [ ] Файлы: ...
- [ ] Описание изменений

### Presentation слой
- [ ] Файлы: ...
- [ ] Описание изменений

### Порядок реализации
1. Domain (сначала — без зависимостей)
2. Application (зависит от Domain)
3. Infrastructure (реализует Port из Application)
4. Presentation (использует всё вышестоящее)
```
